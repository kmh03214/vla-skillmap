03 / 자가발전 파이프라인

학습은 반복하고,
승격은 증거로.

자가발전의 첫 목표는 자동 재학습·평가·후보 생성을 연결하는 것입니다. 새 skill 명명과 실제 실행 권한의 부여는 서로 다른 단계로 관리합니다.

닫힌 루프의 7단계

01CollectLeRobot snapshot + skill calls + 개입·실패
02Segment운동학 + latent change로 구간 후보
03LabelVLM proposal + weak rule + unknown
04Reviewsplit·merge·rename + quality audit
05Train선택 manifest를 고정하고 재학습
06Evaluate독립 gold / OOD / 기존 skill 검사
07Promote통과 시 release, 회귀 시 rollback

검수 budget의 초기 배분

50% disagreement / failure
30% rare skill / novelty / diversity
20% 무작위 audit

이 비율은 초기 가설입니다. audit는 high-confidence 자동 라벨의 숨은 오류와 selection bias를 측정합니다. 비용 비교에서는 검수·경계 편집·재검수·설정 시간을 모두 포함하고, duplicate/retake episode는 같은 split에 묶습니다.

상태를 하나의 줄로 섞지 않습니다.

Annotation state

candidate → pseudo_labeled → human_verified
             ↘ rejected / superseded

Confidence가 높아져도 human_verified로 자동 바뀌지 않습니다. semantic correctness와 outcome correctness의 audit도 별도로 둡니다.

Executable release state

candidate → validated → shadow → canary → active
                              ↘ rolled_back

라벨 검수 완료가 실행 가능한 policy를 뜻하지 않습니다. 지원 시작 상태·검증기·실행 범위까지 평가한 contract만 승격합니다.

실패 데이터의 학습 처리

실패 trace는 오류 분류·negative precondition·recovery 학습에 사용합니다. 실패한 action 전체를 성공 행동과 같은 behavior cloning target으로 섞지 않습니다. 성공한 recovery 구간이나 teleop correction을 선별하고 outcome / validity mask를 남깁니다.

자기강화 오류와 drift를 제어합니다.

Teacher와 audit를 분리

학습 중인 policy의 pseudo confidence를 정답 근거로 쓰지 않습니다. version이 고정된 annotation teacher와 독립 gold set으로 재평가하고, 반복 채택된 오라벨을 revision으로 추적합니다.

Skill candidate의 승격

새 cluster 발생 → 장면 변화·기존 skill 변형·failure mode 여부 확인 → 반복 evidence 확보 → 필요 시 ontology 확장 → execution contract 검증. cluster 생성만으로 skill을 만들지 않습니다.

권장 운영 주기

초기에는 주간 batch release로 운영합니다. 신규 데이터 수집과 자동 후보 생성은 지속 실행하되, training snapshot과 평가 split은 고정합니다. 장기에는 자동 gate를 통과한 기존 skill 업데이트부터 승격을 자동화합니다. 새로운 물리 skill의 실행 범위 변경에는 별도 검증이 필요합니다.
