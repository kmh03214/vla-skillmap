08 / 4주 feasibility PoC

첫 질문은
라벨링에 도움이 되는가?

모델 구조를 크게 바꾸지 않고 시작합니다. latent를 더한 라벨링이 운동학 + VLM보다 유용한지, 같은 품질에 필요한 사람 시간을 줄이는지 4주 안에 판단합니다.

권장 데이터·ontology·split

항목초기 설정 제안이유
데이터240 episodes, 6 task families × 40, 단일 embodiment기존 데이터가 적으면 120 episodes로 시작; 희소 class 통계는 제한
Skillapproach / grasp / lift / transport / place-release / unknown6개 고정 classes. 실패는 별도 outcome axis; pick은 composite
라벨 구간atomic level 한 track부터; 복합·양팔은 후속첫 PoC에서 taxonomy와 overlap 복잡성을 제한
Split144 train / 48 validation / 48 locked testsession·object instance·retake group으로 분할. frame random split 금지
Test 구성ID / OOD strata를 구분해 각 24 episode 목표OOD는 held-out object/layout 그룹. 표본이 작아 slice별 CI 필수
Goldvalidation 48 + test 48, seed train 24 episode평가 gold와 train seed 비용 별도 기록. test label·clip은 teacher tuning 금지
라벨 합의gold의 20%를 2인이 독립 labeling → adjudicationlabel agreement·boundary 허용 오차·unknown 규칙을 먼저 확보
표본 설정은 보유 데이터에 맞춰 조정

240은 필수 요건이 아닌 설계 예시입니다. 같은 trajectory의 crop·augmentation·duplicate는 반드시 같은 split에 둡니다. 희소 skill마다 gold segment가 충분하지 않으면 class 수를 줄이고 OOD slice를 탐색 결과로 보고합니다.

필요 자원과 fallback

항목최소 구성산정 / 대안
사람ML/데이터 담당 1명 + 도메인 검수자 1명; 일부 gold 2인 검수별도 전담 인력 수가 아니라 역할. annotation 시간을 실제 stopwatch로 기록
GPU기존 VLA 추론이 가능한 GPU 1대; frozen extraction은 offline batchGPU가 작으면 compact latent만 cache하고 probe는 CPU. 전체 재학습은 후속
Video teacher멀티뷰 clip을 처리하는 고정 VLM/video model총 비용 = clip 수 × 호출당 비용 + 재시도. budget 부족하면 cluster exemplar + audit만 label
운동학EE pose·gripper가 있으면 바로 boundary baselinejoint state만 있으면 검증된 FK 사용. grip/pose 정보가 없으면 가능한 label을 제한
Stellar hookcheckpoint·cluster posterior·router hook이 실제 접근 가능해야 함접근 불가면 frozen VLA embedding + train-only k-means probe로 map utility부터 검증; Stellar 재현이라고 부르지 않음
추출 시간GPU hour = inference_calls × measured call seconds / 3600240 ep × 20s × 5 calls/s × 0.1s = 약 0.67 GPU-hour 예시. I/O·VLM·training 제외

같은 예산에서 얼마나 검수할 수 있나?

아래는 작업량 계산입니다. 모델 성능 예측값이 아닙니다.

240예상 검수 segment 수

60 / 120 / 240분의 세 training query budget으로 learning curve를 만듭니다. seed와 평가 gold는 shared 고정 비용으로 분리해 보여주고, 총비용 비교에서는 다시 더합니다. 같은 segment 수보다 같은 person-time 비교가 주 평가입니다.

Feasibility의 범위

이 4주 PoC는 Skill Map을 만들고 검수 비용을 줄일 가능성을 검증합니다. robot task success 향상은 후속 rollout 실험으로 확인해야 합니다. 실제 데이터 처리나 학습·로봇 실험을 이미 수행했다는 뜻은 아닙니다.
