Rollout과 통계: pilot를 과대해석하지 않습니다.

평가초기 규모 제안보고 방식
Simulation pilot6 tasks × 30 initial states × 3 training seeds / arm초기 상태 paired. seed별 SR + episode/task 단위 CI; 한 seed의 trial을 독립 model seed로 취급 금지
실제 로봇 pilot선택 2 tasks × 20 initial conditions / armarm 순서 randomize; calibration·성공 기준 고정. 40 trials는 큰 효과·오작동 탐색용
확증 평가pilot effect와 task 변동성으로 사전 power 계산SR≈70%, 5pp 차이는 독립 두 군 가정 약 1,200–1,600 trials/arm 규모가 필요할 수 있음
Annotation qualitylocked episode group bootstrapF1 difference·cost ratio의 95% CI, class support 표시
Paired SR동일 초기 상태의 success/failurepaired bootstrap 또는 discordant pair 기반 검정. task/seed 계층 의존성 고려
5pp를 pilot의 “유의한 향상”이라고 단정하지 않기

약 70% SR에서 5pp 검출 예시는 두 비율의 근사 power 계산(α=0.05, power=0.8)입니다. 실제 표본 수는 paired 구조·task variability로 다시 계산합니다. 40–50 real trials의 넓은 CI를 표시하고 비유의 결과를 “효과 없음”으로 바꾸지 않습니다.

M2–6: 두 번의 closed-loop update

Loop A · Random control

동일한 실패 수집 budget에서 random episode를 검수·추가합니다. 원본 replay quota와 training steps를 고정합니다.

Loop B · Skill Map engine

disagreement·rare skill·failure attribution으로 episode를 선택합니다. 검수·수집·학습의 총시간을 A와 맞춥니다.

Update 0 → 1 → 2마다 new-task SR, old-task SR, forgetting, 잘못된 skill call, pseudo 오류율을 기록합니다. 같은 seed bank·snapshot protocol을 사용하고 고정 gold를 바꿔 test를 쉬워지게 하지 않습니다. Task order는 최소 3개 순서 또는 그 한계를 명시합니다. Stellar VLA ↗ LIBERO ↗
