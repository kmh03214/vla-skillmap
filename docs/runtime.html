05 / Agent 연결

Agent가 선택하고,
로봇이 증명합니다.

처음에는 skill library 전체를 구현할 필요가 없습니다. 반복적으로 성공 가능한 2–3개 composite skill과 고정 planner부터 시작해, 학습된 VLM planner의 추가 효과를 비교합니다.

느린 reasoning과 빠른 실행의 경계

VLM / AGENT목표·대상·계획·예외 처리skill 경계·실패·사용자 지시 변경 때 호출
SKILL SUPERVISOR가용성·precondition·timeout·검증상태 버전과 관측 freshness 검사
VLA / LOCAL EXECUTOR관측 → action chunkexecutor scope·action 단위·control mode 고정
CONTROLLER / SAFETY독립 제한·watchdog·중단planner 응답에 의존하지 않는 local loop

주기는 플랫폼 측정 후 설정합니다. 임의의 30 Hz나 1초를 요구사항으로 고정하지 않습니다. P95/P99 inference latency, action age, deadline miss, planner 대기 시간을 분리해서 기록합니다.

Bounding box에는 camera·좌표 규약·관측 시간을 붙입니다. 오래된 target grounding은 갱신해야 합니다. Planner가 보낸 임의 safety limit을 그대로 사용하지 말고 로컬 contract에 설정된 허용 범위 안에서 요청을 검증합니다.

첫 agent 실험: 비교 가능한 3개 구조

구조목적통제
고정 sequence / state machine + VLAwrapper와 verifier의 효과 측정동일 executor·동일 targets·같은 retry budget
VLM planner + VLA, verifier 없음계획의 이득과 unchecked 실패 측정동일 초기 상태·계산비용 기록
VLM planner + contract + verifier닫힌 실행 loop의 추가 효과 측정recovery와 retries를 포함한 총 시간·성공률
학습되지 않은 호출 범위를 검증

기존 VLA가 전체 trajectory에만 학습됐다면 임의 atomic phase에서 재시작을 잘한다고 가정할 수 없습니다. acquire/place 같이 시작 상태가 검증된 composite부터 expose하고, staging state·skill transition·중간 재시작을 별도 평가합니다.

학습 데이터와 runtime를 함께 성장시키는 방법

동일 stable skill ID 아래에 여러 execution realization을 둡니다. 예를 들어 acquire_object@robot-A와 acquire_object@robot-B는 다른 checkpoint·action schema·calibration·valid scope를 가집니다. 상위 agent는 의미와 조건을 검색하고 supervisor가 실제 executor를 선택합니다.

Skill contract YAML 펼치기
skill_id: manipulation.acquire_object
contract_version: 0.1.0
semantic_level: composite
children: [approach, grasp, lift]
arguments:
  object_id: required
  target_pose_frame: robot_base
preconditions: [target_grounded, reachable, gripper_empty]
termination: [postcondition_satisfied, timeout, abort, safety_stop]
postcondition: object_held_and_clear_of_surface
executor:
  policy_checkpoint: PIN_CHECKPOINT_SHA
  embodiment: PIN_ROBOT_CONFIG
  calibration_id: PIN_CALIBRATION
  supported_start_states: PIN_VALIDATED_SCOPE
  action_schema: PIN_FRAME_UNITS_JOINT_ORDER
  max_duration_s: SET_FROM_MEASUREMENTS
  retry_budget: 1
verification:
  model_version: PIN_VERIFIER
  result: [success, failure, unknown]
fallback: controlled_stop_then_human_review
release_status: candidate
